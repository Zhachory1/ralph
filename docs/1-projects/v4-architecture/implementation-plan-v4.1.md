# Ralph v4.1 implementation plan

**Delivery target:** give the Orchestrator a goal in Paperclip and get a tested draft PR back in the Director's merge queue. Nobody should have to assign the Author by hand, copy an answer out of stdout, launch an OpenCode session, or paste a verdict onto the board.

The [v4.1 design](ralph_v4.1.md) defines the roles and policy; the [v4.0 PDF](ralph_v4.pdf) is the historical source. This plan uses the existing rollout issues. Publishing it does not approve an initiative RFC, enable a schedule, or authorize cutover.

## First delivery: two requests through one organization

Use a sandbox company and the existing `ralph-canary` clone. Keep the earlier, manually assigned Author trial as a failed baseline. Create a **fresh intake**; give only the Orchestrator the goal. Do not seed a manager assignment, specialist task graph, or scripted answers in the live run.

## How to execute and record progress

- **Reuse before editing.** For each row, inspect the linked worker or provisioner, the pinned native capability and the relevant existing canary. Add a failing behavior check for the missing handoff; don't rebuild a parallel control plane, scheduler, worktree manager or approval UI.
- **Keep the unit of delivery small.** A row is a verifiable outcome, not an instruction to open a PR per bullet. Prefer one reviewed patch per concern; plan at most two implementation PRs per issue across repos before revisiting scope. Changes to a production route or permission boundary are separate from merging code.
- **Record evidence in the existing issue.** Identify the environment (fixture, sandbox or actual target), actor and run IDs, source issue, expected artifact, observed artifact and relevant commit/revision or receipt. Link restricted evidence from its authorized board; do not copy private messages, credentials or raw logs to public GitHub.
- **Stop on a failed handoff, not on optional polish.** If a seat exits successfully with no deliverable, leave the task incomplete and fix that assignment or contract. Do not manufacture the artifact outside Paperclip. A closed component PR does not close its tracker until the tracker’s end-to-end evidence exists.
